## Context

已存在 Fire 12 项、共用 CanvasTexture 播放器、四种呈现和离线预览工具。固定上游实际为 244 项、21 类，其中 73 项带 `act` 与示例角色。Fire 的原火环入口继续使用纯特效；新增 72 项角色效果需要 `createAct` 才能展示预备动作、身体状态和命中反馈。

## Goals / Non-Goals

**Goals:** 补齐 232 项独立入口与预览，保留原生动作、原生分类、透明像素、基本参数及完整来源记录。

**Non-Goals:** 不增加 3D 模型绑定、屏幕全局接管、路径编辑、调色板或新渲染后端，不创建额外 Gallery，不引入库依赖或 shader。

## Decisions

1. 本地复制全部分类目录与相对依赖，仍不复制 `src/fx/index.js`。Vite glob 仅按模块懒加载，元数据不静态导入效果源码。原有 Fire type/路径保持兼容，新增 type 加类别前缀避免重名。
2. 使用统一元数据描述分类、中文名、简述、默认 loop 和播放方式。注册由全量元数据生成，每个效果仍有独立 Vue 薄入口，参数沿用已有六项。分类词加入目录名称以便现有搜索使用。
3. 新增角色效果使用原 `createAct/actBounds/actSpan`；bounds 扩大画布并同步重算 origin，保留角色脚下的组件锚点。开始时间包含负值 wind-up，动作结束依据实际时间和命中停顿，不按单纯墙钟截断。原生循环持续推进；单次效果开启循环时重新建立整个实例。
4. 原生画面 shake 在复用 RGBA 缓冲中平移，输出纹理与预览使用同一逻辑。暂停、速度为零、卸载和资源管理继续沿用现有协议。
5. UI、全幅天气和转场保留原始 size/origin，仍绘制为当前场景内的透明平面。转场的遮罩只是该平面内容；不修改相机、DOM、renderer 或其他场景对象。
6. 扩展离线脚本到全库，保留既有 Fire 素材，通过逐项输入签名跳过有效资产；每项记录角色模式、实际帧数、时长与首帧。采样完整周期，包括预备、命中停顿、恢复和单次间隔，转换失败不伪造资产或静默漏项。

## Risks / Trade-offs

- 角色模拟和全幅像素绘制成本较高 → 原生 fps 更新、缓冲复用、按需加载；CPU 检查不代表移动端 FPS。
- 角色图形是原项目像素示例 → 名称/说明明确来源，不声称已与用户三维模型绑定。
- 原生 act 的命中停顿需要单独消耗时间 → 固定步长推进原生 update，并依据原生完成状态结束，不按预估时长截断。
- 转场可能覆盖整张局部纹理 → 保留透明起止与正常深度测试，说明其局部平面语义。
- 全量预览资产比首批大 → 继续使用现有 poster 懒加载和 hover 动图，不改通用目录 UI。

## Migration Plan

在原目录追加组件和注册即可。回滚恢复共用文件、全量注册、离线脚本和文档，移除本批新增目录与素材；原 Fire type 及原生纯特效逻辑不依赖新角色入口。严格遵守 AGENTS.md 的构建/调试边界。
