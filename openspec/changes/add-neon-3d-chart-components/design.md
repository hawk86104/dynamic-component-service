## Context

现有服务用 TresJS 承载 Three.js 对象，通过 `dcsConfig.ts` 自动发布 federation 模块。参考图一为不同高度的玻璃质感环形扇区；图二为沿 Z 轴分离的平滑面积实体，具有蓝青至黄绿/珊瑚色顶面。

## Goals / Non-Goals

**Goals:** 两个可独立使用的组件；JSON 驱动数据；几何、渐变和标签可调；环图突出玻璃反射与磨砂质感，面积图重点还原彩色曲面和蓝紫侧壁的分层玻璃效果；与现有预览及导出机制一致。

**Non-Goals:** 不创建 Canvas/相机/灯光或改动通用视图；不依赖远程资产、后处理或第三方图表库；不实现悬浮交互与实时流式动画。

## Decisions

- 环图以数值决定角度；高度可按值缩放、统一高度，或由每项可选 `height` 指定。使用圆角挤出扇环而不是同心圆柱，保留真实侧壁和空心结构。
- 面积带以 `categories` + `series[].values` 描述等距分类轴；所有序列共享 Y 轴尺度。单调三次插值避免 Catmull-Rom 在局部峰值处过冲或低于零；`smooth: false` 使用折线。每条序列为封闭实体，支持单点数据与全零数据。
- JSON 支持既有 JSON5 编辑器；维持上一次有效数据，语法或语义错误通过 `data-error` 事件和公开 `dataError` 返回，成功后清空。支持直接更新 `jsonText` 和已有的 `jsonTextChangeNumber` 刷新协议。
- 公共工具只处理数据校验、底座/标签/轮廓与资源释放。两套 shader 分别位于组件同名目录，环图沿高度着色，结合世界方向的程序化柔光箱反射、Fresnel 透明度、厚度着色及经过像素覆盖衰减的细微磨砂；面积图沿 X 轴三色渐变。高光无需 Bloom、外部环境贴图或宿主灯光也可显示；不采样场景画面，不声称实现真实折射。
- 环图倒角几何合并同位置顶点并重新计算平滑法线，使条形反射连续；透明模式采用双面前后两次绘制和较弱背面着色，呈现内外壁层次，不写入深度。`opacity=1` 时切换单面与深度写入，保留完全不透明模式。shader 接入对数深度以适配宿主。
- 标签使用世界空间 Sprite/CanvasTexture，图表本体为真实 mesh。环图移除底座四项参数，面积图移除底座/背板/网格五项参数及相关实现，图表底部均位于局部 y=0。环图通过 `reflectionStrength` 调反光、`roughness` 调反射模糊和磨砂，降低默认不透明度以强化通透层次。几何和材质只在参数改变时重建，清理旧资源；不持续占用渲染循环。
- 输入上限为 32 个扇区、8 条序列和 128 个分类；校验有限数值、非负数据、同长序列及十六进制色值，限制细分数和尺寸，避免异常输入拖垮页面。

## 面积图参考图重构

- 原实现对顶面、侧面统一使用 X 渐变，曲面由独立平面法线组成，固定颜色轮廓掩盖了蓝青/黄绿和蓝紫/珊瑚两套配色。重构为独立的几何、材质与参数层。
- 横截面用各四段细分的圆弧连接顶面和两侧壁，圆角半径随厚度和局部高度约束；沿 X 的顶面法线取采样曲线切线，跨采样段保持连续。底面与端面维持硬边和向外朝向，不改变原始峰值、宽度或地面高度。
- 几何额外提供顶面权重和相对局部曲高，shader 据此分别计算顶面三色渐变与侧面从顶部到地面的蓝紫梯度，渐变不会因不同峰高而断层。顶面保留更实的磨砂色，侧面更通透；柔光箱反射、Fresnel、微表面颗粒和横向反光带叠加在上述底色之上。反光带由观察方向和曲面法线决定，不画固定位置条纹；不采样或折射宿主场景。
- 轮廓改为随 X 变化的顶面同源渐变色，在圆角肩部放置细轮廓，在首尾加横向高光；不使用贯穿整条曲面的固定白/绿粗管。所有 shader 仍置于组件专属目录，保留对数深度兼容。
- 默认只显示两条曲面和峰值卡片：底座、网格、围挡实现及对应五项设置全部移除，组件始终从局部 y=0 起算；保留默认关闭的坐标标注。反射强度、磨砂、圆角、侧面颜色、侧面纵向梯度和侧面透明度均同步至参数面板。
- 侧色保留用户输入的 RGB 通道，不再由蓝色通道重建蓝紫偏色；纵向渐变直接调节底到顶的亮度及通透变化，反射叠加量降低并按侧色着色。侧面不透明度支持 0～1，乘在完整侧面 alpha 上，没有独立的残留 Fresnel alpha；整体不透明度为 1 不再覆盖侧面设置。仅两项不透明度都为 1 时关闭透明绘制并开启深度写入。纯材质工厂独立为 `material.ts`，CPU 回归可验证实际材质状态和 uniforms。
- 初步 CPU 追踪只能证明新编译实例中的 `#0033d8` 和红/绿色能到达 props 和 uniforms，不能证明已有开发页面的编译结果正确。面积实体使用两个连续绘制组：组 0 承载顶面和圆角肩部，组 1 承载两侧壁、端面、底面；组 1 使用独立 `MeshBasicMaterial.color` 直接绑定侧色，走 Three.js 原生 diffuse 更新路径。用射线命中验证可见墙面和端面的 materialIndex 为 1，而不是仅检查 uniforms。
- 侧面渐变写入中性的顶点 RGBA：RGB 三通道相同，负责上下明暗；A 负责通透变化，材质 opacity 负责整体与侧面系数。独立 `side.vert` / `side.frag` 在原生 shader 之后添加仅改变亮度的反射与磨砂，保留输入颜色的色相，不叠加固定白色。绘制数据按两组连续排列，避免逐段分组增加绘制调用。
- 用户授权页面调试后，通过 Chrome 当前运行脚本确认导入类型的旧编译结果缺少 `bevel`、`reflectionStrength`、`roughness`、`sideColor`、`sideGradient`、`sideOpacity`，仍声明已删除的底座字段；运行时默认值却已更新，导致 Vue 警告和 `color: undefined`。组件改用 `RIBBON_AREA_PROPS` 显式运行时声明，所有默认值仍引用 `RIBBON_AREA_DEFAULTS`，不依赖导入类型缓存生成 props；回归覆盖全部字段、默认值和 Vue 响应式更新。
- 检查重点为实体闭合/朝向、圆角边界、曲面法线连续性、数据峰值不变与默认值/面板一致。用户授权后已在实际页面验证三种侧色、渐变与透明度，完整参考图还原度不作为本次缺陷修复的验收结论。

## Risks / Trade-offs

- [透明面排序受视角影响] → 使用封闭实体、合理透明度及独立轮廓，允许调至不透明。
- [大量标签重叠] → 标签可关闭；环图使用径向外置标签与引导线，面积图仅标注峰值。
- [无后处理时辉光范围有限] → 用明亮轮廓和 Fresnel 高光实现基础风格，宿主可自行接入 Bloom。
- [静态检查无法发现已有页面的编译缓存问题] → 按 AGENTS.md 在用户明确授权后调试实际页面，并将浏览器结果与 CPU 检查分开记录；本次未运行生产构建。
